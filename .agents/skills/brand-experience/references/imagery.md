# Imagery profile

Use for selecting, briefing, generating, editing or adapting photography, illustrations, diagrams, iconography, hero/title images and article covers. This is not an independent brand-discovery workflow. Read the shared contract first.

## 1. Establish the image's job

Read the relevant audience/message in `experience.md`, global art direction and applicable IMG/DES rules in `design.md`, applicable placement pattern, theme color roles, asset records and visual references. Identify subject, intended meaning, placement and whether imagery genuinely helps. Choose reuse, generate, edit, omit or an explicitly temporary fallback. A new image is not obligatory for every page.

Identity assets are fixed: use actual registered originals and correct variants. Do not recreate a logo or invent a standalone mark. A title treatment may be live text plus a photograph and overlay; preserve the separate image asset and composition recipe. A campaign hero need not become a timeless identity artifact.

## 2. Resolve a brief before generation

Combine reusable art direction with the task subject and placement. Record purpose, subject/setting, viewpoint and framing, focal point/negative space, lighting, color/contrast/texture/realism, appropriate people/actions, aspect-ratio intent, target dimensions, safe crop/text zones, desktop/mobile transformations, authenticity and avoidances. Include actual permitted reference files and what each demonstrates. `templates/imagery-brief.md` is available; a small task can use a concise section of its existing plan.

For icon/diagram work, also specify visual weight, semantic clarity, size and relationships. Preserve technical correctness rather than merely decorating an uncertain diagram. Reuse established icons or real asset files where appropriate. Do not turn every missing asset into a generated photograph.

## 3. Execute using actual tools

Check whether the environment provides an image-generation/editing capability and whether the selected reference material can be sent to it. Use the actual tool rather than presenting a prompt as the generated image. Do not invent API credentials, install unrelated providers, upload privately held assets elsewhere or claim unavailable tools. If generation is unavailable, deliver the resolved brief and a disclosed permitted fallback; name the generation step as unperformed.

Editing a specific existing image requires the actual usable target. Locate and inspect that file; an opaque ID, filename or earlier claim of approval is not sufficient access. If missing, ask for that target or deliver unaffected planning only. Do not generate a substitute and call it an edit.

Generate/select recurring imagery once and reuse the actual file across relevant screens. Do not crop pretend editable assets out of a flattened application mockup. Follow host image-tool message/output rules; not every image-only turn can create a sidecar or update a screen document.

## 4. Verify and place

Where files are accessible, verify that bytes exist, file type and actual dimensions, expected composition, crop resilience and obvious artifacts. Report actual delivered dimensions, not a size merely requested from the generator. Do not equate a 300-PPI metadata flag with additional visual detail. Check permitted use, sensible alt text and web placement. Preserve originals; write clearly identified derivatives rather than overwriting source assets.

Save new task-specific output in the existing task/app asset path; retain a short provenance/placement note in the plan, screen spec or existing asset record. Include the source rule/brief, actual tool/model only if known, generation/edit date, verified dimensions and authenticity. It is illustrative unless supported as a real client artifact. Do not claim generated scenes show completed projects, actual employees or verified results.

For a web deliverable, use the web profile to integrate/optimize the image and inspect responsive crops. Only an explicit kit-maintenance request promotes a task image to `/brand-kit/assets/` with proper registration. Do not package or deliver font binaries.
